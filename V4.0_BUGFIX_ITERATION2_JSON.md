# v4.0 Bug Fix: Iteration 2+ JSON Truncation

## 🐛 Bug Discovered During Testing

**Date:** 2026-06-28  
**Severity:** High (blocks iteration 2+)  
**Status:** ✅ FIXED

---

## 📊 What Happened

### Logs Showed:
```
Iteration 1 - ATS Score: 78 ✅
⚠️ ATS score 78 below target (85). Requesting improvement (iteration 1/4)

Claude API attempt 1 failed: Unexpected end-of-input: was expecting closing quote ❌
Claude API attempt 2 failed: Unexpected end-of-input: was expecting closing quote ❌
Iteration 2 failed: Unexpected end-of-input: was expecting closing quote ❌
```

**Symptoms:**
- ✅ Iteration 1 works perfectly
- ❌ Iteration 2+ fails with JSON parsing errors
- ❌ "Unexpected end-of-input" → JSON truncated mid-string

---

## 🔍 Root Cause

### Problem 1: Insufficient Token Limit

**Previous setting:**
```properties
aws.bedrock.max.tokens=800
```

**Issue:**
- Initial prompt output: ~600 tokens (fits in 800)
- Improvement prompt output: ~1200 tokens (needs more space)
- Result: Claude's response gets cut off mid-JSON → parsing fails

**Why improvement needs more tokens:**
- Must include: previous bullets (4 × 150 chars)
- Must include: previous score + reasoning
- Must include: all improvement instructions
- Must include: new tailored bullets

**Calculation:**
```
Initial prompt output:
- titleLine: ~100 tokens
- experienceBullets: ~400 tokens
- atsScore + reasoning: ~100 tokens
Total: ~600 tokens ✅ Fits in 800

Improvement prompt output:
- Previous attempt context: ~300 tokens (NEW!)
- titleLine: ~100 tokens
- experienceBullets: ~500 tokens (longer, more keywords)
- atsScore + reasoning: ~200 tokens (more detailed)
Total: ~1100 tokens ❌ Doesn't fit in 800
```

---

### Problem 2: No Validation

**Previous code:**
```java
JsonNode tailoredContent = objectMapper.readTree(cleanedJson);
return tailoredContent;  // Assumes valid
```

**Issue:** No check if response has required fields

---

## ✅ Fix Applied

### Fix 1: Increase Token Limit

**File:** `src/main/resources/application-dev.properties`

**Change:**
```properties
# BEFORE
aws.bedrock.max.tokens=${AWS_BEDROCK_MAX_TOKENS:800}

# AFTER
aws.bedrock.max.tokens=${AWS_BEDROCK_MAX_TOKENS:2000}
```

**Why 2000?**
- Iteration 1: uses ~600 tokens (safe margin)
- Iteration 2+: uses ~1200 tokens (safe margin)
- Buffer for edge cases: +800 tokens
- Cost impact: minimal (output tokens priced same regardless)

**Cost Impact:**
```
Before: 800 max tokens
After:  2000 max tokens

Actual usage:
- Iteration 1: ~600 tokens (no change in cost)
- Iteration 2+: ~1200 tokens (was truncated, now complete)

Cost per resume: Still ~$0.021 (no increase, just fixes truncation)
```

---

### Fix 2: Add Response Validation

**File:** `src/main/java/com/jobtracker/jobtracker/service/ResumeTailoringService.java`

**Change:**
```java
// Parse JSON from cleaned response
JsonNode tailoredContent = objectMapper.readTree(cleanedJson);

// Validate response has required fields (NEW!)
if (!tailoredContent.has("atsScore") || !tailoredContent.has("experienceBullets")) {
    throw new RuntimeException("Incomplete response: missing required fields (possible truncation)");
}

log.info("Claude API success (iteration {}, attempt {})", iteration, attempt);
return tailoredContent;
```

**Why?**
- Early detection of truncation
- Clear error message
- Triggers retry logic
- Better debugging
