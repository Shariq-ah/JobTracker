### 2. callClaudeForTailoring() - Complete Rewrite

**BEFORE:** Single API call, no iteration
**AFTER:** Iterative loop with early stopping

**Key Features:**
- ✅ Loops 1-4 times
- ✅ Checks `atsScore >= 85` after each iteration
- ✅ Stops early on success
- ✅ Dynamic prompt: iteration 1 uses initial, 2+ uses improvement
- ✅ Clear logging at each step
- ✅ Returns best attempt even if < 85%

**Iteration Flow:**
```
Iteration 1 → Initial Prompt → Score 72 → Continue
Iteration 2 → Improvement Prompt → Score 78 → Continue
Iteration 3 → Improvement Prompt → Score 87 → STOP ✅
```

---

### 3. invokeClaude() - New Method (Extracted)

**Purpose:** Separate API invocation from iteration logic

**Features:**
- Handles AWS Bedrock API calls
- Retries on network errors (2 attempts)
- Exponential backoff (2s, 4s)
- JSON parsing with markdown fence stripping
- Returns structured JsonNode

**Why Extracted:**
- Cleaner code separation
- Easier to test API calls
- Iteration loop stays focused on logic

### 4. buildInitialPrompt() - Renamed

**BEFORE:** `buildOptimizedPrompt()`  
**AFTER:** `buildInitialPrompt()`

**Change:** Name only (content unchanged)  
**Why:** Clearer distinction from improvement prompt

### 5. buildImprovementPrompt() - New Method

**Purpose:** Build coaching prompt for iterations 2+

**What It Does:**
1. Shows Claude its previous score and bullets
2. Analyzes why score is low
3. Lists specific improvements needed
4. References job requirements again
5. Sets aggressive tone to push for 85+

**Prompt Structure:**
```
Previous Score: 72
Why It's Low: Missing Docker/K8s keywords

IMPROVEMENT INSTRUCTIONS (BE AGGRESSIVE):
1. INCREASE keyword density
2. Front-load bullets
3. Use EXACT terminology
...
10. Target 85+ ATS score

YOU MUST IMPROVE THIS ITERATION.
```
