# JobTracker Fixes - June 14, 2026

## Issues Fixed

### Issue 1: Lock Timeout (1-2 jobs per run)
**Error**: `Interrupted waiting for lock`

**Root Cause**: 
The synchronized block in `saveMatchedJob()` was holding the lock for **7+ seconds** while:
- Saving to MongoDB (~100ms)
- Sending Telegram notification (~500ms)
- **Generating tailored resume (~5s)**
- Sending resume PDF (~2s)

This blocked all other threads from saving jobs, causing timeouts.

**Fix**:
Moved all non-critical operations (Telegram + resume generation) **outside the synchronized block**. Now the lock is only held for:
- DB duplicate check (~10ms)
- DB save (~100ms)

**Result**:
- Lock duration: **7s → 0.1s** (70x faster)
- No more lock timeouts
- Threads no longer blocked by resume generation

---

### Issue 2: General Resume Telegram Send Failure
**Error**: `Failed to send general resume via Telegram: Error writing request body to server`

**Root Cause**:
- Intermittent network issues with Telegram API
- Connection pooling problems
- No retry logic

**Fix**:
1. Added `Connection: close` header to prevent connection pooling issues
2. Added retry logic (2 attempts with 1s delay)
3. Fallback to text-only notification if PDF send fails

**Result**:
- Resilient to network hiccups
- Graceful degradation (text notification if PDF fails)

## Issue 3: Development Testing Costs Money

**Problem**: Every local test run costs ~$0.04 ($12/month for 10 tests/day)
- JD extraction: $0.001 × 20 jobs = $0.02
- Resume tailoring: $0.004 × 5 resumes = $0.02

**Solution**: **Development Mock Mode**
- Added `ai.dev.mock.enabled` configuration flag
- When `true`: Uses mock responses (zero cost)
- When `false`: Uses real Bedrock API (production)

**Mock Features**:
- Realistic score variation (60-95% match, 75-94% ATS)
- Adjusts for keywords (Spring Boot, Kafka, etc)
- All downstream logic still works (DB, Telegram, LaTeX)

**Savings**: **100% of development costs** ($12/month → $0)
